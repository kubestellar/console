# Red Hat and OpenShift Outreach Plan

This guide packages the KubeStellar Console OpenShift story for partner outreach, blog submissions, and conference planning.

## OpenShift-native support summary

KubeStellar Console already has a credible OpenShift story:

- `deploy.sh --openshift` enables an OpenShift Route workflow
- the Helm chart documents OpenShift route and SCC considerations
- the product includes OpenShift-aware cluster detection and OpenShift-specific views
- OpenShift user and RBAC inventory are already represented in the codebase and UI

## Red Hat Developer Blog pitch

### Working title

**Managing multi-cluster OpenShift deployments with KubeStellar Console**

### Angle

Show how platform teams can use one console to evaluate cluster health, RBAC posture, and project integrations across multiple OpenShift environments without bouncing between tabs or clusters.

### Outline

1. Why OpenShift operators still need a cross-cluster view
2. Fast setup with `deploy.sh --openshift`
3. OpenShift-aware cards and identity surfaces
4. Demo mode for evaluation before cluster access
5. How KubeStellar missions can guide follow-up actions

### Call to action

- Try the hosted demo
- Self-host against an OpenShift fleet
- Contribute OpenShift-focused docs, tests, and cards

## KubeCon NA 2026 joint session proposal

### Draft title

**Operating OpenShift fleets with one AI-assisted multi-cluster console**

### Session concept

A joint session with Red Hat or OpenShift ecosystem speakers that combines:

- OpenShift deployment reality across multiple clusters
- how the console reduces operational context switching
- what AI-assisted missions add without replacing operator control

### Submission checklist

- [ ] Identify Red Hat or OpenShift Commons co-speaker
- [ ] Capture one OpenShift demo scenario
- [ ] Prepare 3 audience takeaways
- [ ] Submit before CFP close

## OpenShift Commons outreach plan

- Share the blog draft with OpenShift Commons organizers
- Request a short demo slot or community spotlight
- Bring one concrete multi-cluster operations story, not a generic product pitch
- Offer a follow-up contributor issue list for OpenShift-native users

## Success metrics

- One Red Hat Developer Blog submission sent
- One KubeCon NA 2026 session abstract drafted and reviewed
- One OpenShift Commons conversation or showcase scheduled
- At least 2 follow-on OpenShift issues or docs PRs opened by community members
