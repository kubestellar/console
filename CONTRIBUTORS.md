## New contributor onboarding

If this is your first contribution, use this path:

1. Read [CONTRIBUTING.md](CONTRIBUTING.md) for workflow, DCO, testing, and PR expectations.
2. Join the community channels listed in [docs/COMMUNITY.md](docs/COMMUNITY.md).
3. Pick a small issue first:
   - docs updates
   - translations
   - tests
   - labeled onboarding issues such as `good first issue`
4. Comment on the issue so maintainers know you are working on it.
5. Open a focused PR with a clear description and linked issue.

## Good first contributions

The easiest ways to get started are:

- Improve documentation or setup instructions
- Add or expand tests for existing behavior
- Translate existing UI strings
- Triage issues by reproducing bugs and sharing exact steps
- Help review community questions in GitHub Issues or Slack

## Maintainer expectations for welcoming contributors

- Acknowledge first-time contributor PRs quickly
- Point new contributors to the right docs instead of assuming repo knowledge
- Prefer actionable review comments with examples
- Keep docs-only and onboarding PRs moving fast when CI is green
